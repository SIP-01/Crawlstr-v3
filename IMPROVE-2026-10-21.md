# Improvement Deep-Dive — Crawlstr-v3 — 2026-10-21

Scope: browser scout crawler + `scrapling-node/` Python node, both publishing kind 39697. Files read: `README.md`, `package.json`, `scrapling-node/requirements.txt`, `src/crawler/` listing, `.github/workflows/` listing, `NIP.md`.

## Top recommendations (ranked, with effort S/M/L)

1. **Add PR-triggered CI (tsc + vitest + eslint) and protect `main` (S).** Only workflow is a deploy-on-push-to-main. The README itself documents a regression-tested "zero-throughput self-deferral bug" — those regression tests only have value if they run on every PR. `main` is unprotected.
2. **Deduplicate the protocol layer with indexstr-v3 (M).** `src/crawler/` here (flat: `engine.ts` ~45KB, `webIndex.ts` 13561 B, `heartbeat.ts` 5494 B) and indexstr-v3's `src/crawler/internal/` (`engine.ts` ~47KB, `webIndex.ts` 13637 B, `heartbeat.ts` 7622 B) are two diverging copies of the same crawler-core. The size deltas show drift has already happened. Publish one `@sip01/crawler-core` (and `@sip01/protocol`) package; until then, add a CI byte-diff of `webIndex.ts`/URL normalization against the §13 test vectors so drift is at least detected.
3. **Pin the Python supply chain like the JS one (S).** `scrapling[fetchers]==0.4.15` is exactly pinned (good, pre-1.0), but check the Dockerfile/`docker compose` for unpinned base images and `pip install` without `--require-hashes`. `websockets>=12,<16` is a wide range — narrow to `<15` after testing, or pin.
4. **Update ecosystem links from `NostrDanish/*` to `SIP-01/*` (S)** — badge, spec link, and ecosystem table all point at the old org.

## Missing gates (CI/tests/protection)

- No PR CI; no branch protection; direct-to-main pushes observed org-wide.
- Deploy uses `npm install`, not `npm ci` (non-reproducible deploys).
- No dependency-update automation (Dependabot/Renovate) — matters doubly here because `scrapling` is pre-1.0 and the CORS-proxy fetch path is security-sensitive.
- No gitleaks/secret scanning in CI (per-device keypairs are generated client-side, but a committed relay token or proxy key in the Python node would ship silently).

## Quick wins (code/config)

- The README's own changelog shows the adaptive-recrawl/backoff logic is subtle and bug-prone (cap-after-jitter, abort-hang fixes) — extract it into a tested module boundary if not already, and keep the regression tests in CI (see #1).
- `scrapling-node/README` quickstart uses both Docker and raw pip; pick one canonical path and mark the other advanced, to cut support surface. S.
- Add `SECURITY.md` (this repo accepts arbitrary seed URLs from users — the SSRF guard is the security boundary; tell people where to report bypasses). S.

## Ecosystem alignment notes

- Publishes kind 39697 with `source=crawlstr/v3` / `crawlstr/v3+scrapling` — consistent with spec v1.2 and the source-tag lineage (`crawlstr/1` → `v2` → `v3`).
- **NIP-01 changes this week** (#2504: empty filter lists match nothing; #2511: don't send empty lists): audit relay-discovery/heartbeat filter construction — any dynamically built filter array that can come out empty must be omitted, and an empty `filters[]` must never be sent as a REQ.
- NIP-50 autocomplete was added upstream then reverted (June 2026); no reliance found — correct. Crawlstr only *publishes*, so NIP-50 surface is minimal; keep it that way.
- Heartbeat (kind 16919, coarsened counters) is a SIP-01-internal convention — consider documenting it as a registered extension in the spec's §9 registry so third-party indexers can interoperate. S.
